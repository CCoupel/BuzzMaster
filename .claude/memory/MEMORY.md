- **#200 — saga de 7 cycles, 6 causes racines distinctes** pour le symptôme "START possible sans équipe sélectionnée" (MEMORY/MEMOTION, puis RAFALE) : (1) rejeu même question sans reset, (2) `Pause()`/`Continue()` sans garde de phase, (3) broadcast inconditionnel désynchronisant l'affichage, (4) rejeu START→STOP zéro-action, (5) équipe perdant son dernier buzzer (réassignation), (6) même bug via `DELETE_BUMPER` (aliasing de map). **Leçon méthodologique clé** : les 4 premiers cycles ont été statiquement corrects sur leur périmètre mais ont manqué la vraie cause car aucun test ne faisait de round-trip réel disque→WS→engine — un test de ce type (`memory_start_no_team_repro_200_test.go`) a comblé l'angle mort et doit être le réflexe pour toute future investigation similaire (voir aussi `feedback_check_existing_mechanism_before_new_phase.md`).
- **#201 — seuil SOLO/multi rationalisé** : nouveau helper partagé `participantsCountConform(mode, count)` (SOLO=exactement 1, multi=au moins 2) appliqué à MEMORY/MEMOTION/RAFALE — RAFALE SOLO n'exigeait auparavant aucune équipe, RAFALE et MEMOTION multi n'exigeaient qu'1.
- **#202 — pré-tirage RAFALE + zone "SUIVANTE" sur `/anim`** : le moteur pré-tire réellement la question suivante (pas un aperçu jetable) et la consomme au tick suivant ; diffusée via extension additive de `RAFALE_ANSWER` (admin+anim uniquement, jamais dans `GameState` — même régime que la réponse).
- **Site marketing (`gh-pages`, worktree `MARKETING/`)** mis à jour pour v8.0.0 : nouvelle carte RAFALE (6ᵉ mode), captures réelles produites via Chrome headless + vraies manches jouées côté serveur local, texte MEMOTION complété (nidification MEMORY v7.1.0). Le worktree `MARKETING/` fonctionne normalement (le souci de gitlink cassé documenté dans `project_marketing_broken_worktree.md` semble résolu — à vérifier/mettre à jour cette mémoire si confirmé stable sur plusieurs sessions).
