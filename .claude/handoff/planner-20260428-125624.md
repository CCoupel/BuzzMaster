## Décisions clés

1. **#11 — `HandleConnectionWithType` vs `SET_CLIENT_TYPE`** : Le type est fixé à la connexion par l'URL endpoint, plus par `SET_CLIENT_TYPE`. L'action `SET_CLIENT_TYPE` reste acceptée pour retro-compat mais devient no-op si endpoint dédié utilisé.

2. **#11 — PlayerDisplay** : PlayerDisplay.jsx utilise probablement `GameContext` (partagé avec admin). Risque de conflit si context reste sur `/ws/admin` mais PlayerDisplay doit être sur `/ws/tv`. Solution recommandée : ajouter un param `endpoint` à `useWebSocket()` hook.

3. **#41 — Approche whitelist vs serializer** : Choix de la whitelist dans `BuzzerWebSocketHub.BroadcastIfRelevant()` plutôt que `SerializeForBuzzer()`. Plus simple, transparent, ne nécessite pas de refactoring de la sérialisation. Suppression de `buzzerHub.Broadcast(msg)` dans `broadcastUpdate()`.

4. **#54 — AckManager goroutine** : Goroutine unique avec tick = `ack_timeout_ms`. Map en mémoire `map[msgID]AckEntry`. Cleanup automatique sur déconnexion buzzer (OnBuzzerDisconnected callback).

5. **#54 — MSG_ID champ racine** : `MSG_ID` au niveau racine du struct `Message` (pas dans `MSG`), donc visible sans parser le payload — plus simple côté firmware pour détecter et ACKer.

- **Vérifier si d'autres `broadcastXxx()` envoient à `buzzerHub`** : `grep "buzzerHub.Broadcast" main.go` avant de commencer.
- **`AckManager`** : Créer dans `server-go/internal/server/ack_manager.go`. Instancier dans `App` struct. Wiring callbacks dans `app.init()`.
- **Route `/ws/player` dans `http.DefaultServeMux`** : Tester que `"/ws/player"` ne rentre pas en conflit avec les routes existantes (mux Go fait un exact match pour les routes ne finissant pas par `/`).

### dev-frontend

- **Vérifier App.jsx routing** avant de modifier PlayerDisplay : est-ce que `/tv` partage le GameContext avec `/admin` ? Si oui, créer un hook séparé ou paramétrer le hook existant.
- **VPlayerPage.jsx appelle `setClientType('vplayer')` ligne ~78** : Supprimer cet appel si l'endpoint `/ws/player` fixe le type automatiquement.
- **Badge ACK_PENDING** : Style inline React (pas CSS class), identique au badge `CONNECTED=false` (`background:#f59e0b`, SVG stroke:white). Condition : `!bumper.IS_VIRTUAL && !bumper.IS_VPLAYER && bumper.ACK_PENDING === true`.

### firmware-dev (#54)

- **Lire `contracts/buzzer-ack-protocol.md`** avant d'implémenter.
- **ACK avant apply action** : `ws_sendAck()` appelé AVANT d'appliquer le LED_SET/OTA/WiFi.
