**main.go ACK wiring:**
- `sendLEDSet()`: generates MSG_ID, attaches to msg, registers, sets AckPending=true
- `sendWifiConfigToBuzzer()`: per-buzzer MSG_ID + ACK registration
- `broadcastWifiConfig()`: iterates `GetClients()` with individual MSG_IDs (no Broadcast() for ACK'd msgs)
- `handleBuzzerACK()`: parses AckPayload, Confirm, clears AckPending, broadcastUpdate
- `OnBuzzerDisconnected`: calls `ClearByMAC(mac)` to avoid stale retries
- `AckManager.OnRetry`: re-sends LED state via `resendLEDOnReconnect()`
- `AckManager.OnExpired`: clears AckPending after max retries, broadcastUpdate
- AckManager goroutine started in `App.start()` with `context.Background()`
- `httpServer.OnPriorityMessageSent` callback wired for OTA_UPDATE from http_firmware.go

**config.json:** AckTimeoutMs=2000, AckMaxRetries=3 (already in file from earlier)

## Notes for Frontend Agent

No frontend changes required for this backend milestone. The new WS endpoints are immediately available:
- `/ws/admin` — admin web client (full state, questions, config)
- `/ws/tv` — TV display client (game state, no admin-only msgs)
- `/ws/player` — VPlayer client (PLAYER_REJECTED/CONNECTED/ASSIGNED + game state)

Existing `/ws` continues to work as alias (→ Admin type).

The `ACK_PENDING` field on Bumper objects will now appear in UPDATE payloads when a buzzer is awaiting ACK of a priority message. Frontend may optionally display this state.
