## Ce qui a été fait

Ajout de deux tests Go dans `server-go/internal/server/http_port_retry_test.go` :
- `TestIsPortInUse` : vérifie le helper sur erreurs Linux, Windows, et cas non-busy
- `TestHTTPServer_Start_RetriesOnPortBusy` : occupe un port avec un listener temporaire,
  démarre HTTPServer sur ce port, libère le listener après 300 ms, poll jusqu'à réponse HTTP

Ajout d'une procédure manuelle QA dans `tests/procedures/bugfix-http-port-retry.md` :
4 scénarios couvrant : démarrage normal, port occupé puis libéré, self-update complet, 
erreur fatale non confondue avec EADDRINUSE.

## Décisions clés

- Fichier séparé (`http_port_retry_test.go`) plutôt qu'ajout dans `http_test.go` : 
  isolation claire des tests non-régression, conforme à la règle additive.
- Port dynamique (`:0`) via `net.Listen` pour éviter les conflits en CI.
- Blocker libéré à 300 ms < 500 ms (intervalle retry) : garantit au moins un cycle EADDRINUSE.
- Polling toutes les 100 ms sur 3 s : marge confortable sans allonger le CI.

## Points d'attention

- Le test `TestHTTPServer_Start_RetriesOnPortBusy` bind réellement un port TCP local.
  En environnement très restrictif (container sans réseau loopback), il pourrait nécessiter
  un skip conditionnel.
- `config.SetInstance()` est un état partagé de process : le test ne tourne pas en `t.Parallel()`.
